# Lessons

- 在判断 GPU 暴露和映射状态时，优先依据容器内的证据，不要把宿主机截图和容器截图混为一谈。
- 在改模型输入链路前，先用本地源码或已安装包确认接口支持范围，不要凭经验假设只能走文件路径。
- 改“文件路径 -> 内存输入”时，要同时检查 AutoModel 外层和 remote_code 内层的接受类型；这次 Fun-ASR 外层能吃 bytes，但自定义模型实际只接受 `str` 和 `torch.Tensor`。
- 做“速度优化”时，如果改了 speaker 归属或对齐链路，要把精度回归单独验证；不要把“ASR 变快”误当成“切分和声纹路径没动”。
- 做大规模名单选择 UI 时，先按 100+ 选项场景评估信息密度；平铺复选框在会议参会人场景下不可扩展，优先用可搜索多选下拉并用 tag 回显已选项。
- 当前端缓存的数据依赖后端地址时，必须在地址切换时显式失效缓存和已选状态；不要让旧后端的名单继续参与新后端请求。
- 上传音频链路不要假设 `librosa.load(BytesIO(...))` 和上层模型都兼容所有格式/输入类型；内存解码要有文件路径回退，Paraformer 之类的整段 ASR 也要先确认是否实际接受路径字符串。
- 给“参会人白名单”这类候选约束功能加到匹配热路径时，不能把全库模式的严格 guard 语义和逐次筛选实现原样复用；要预构建请求级候选矩阵，并单独评估有限候选集下的阈值/未知语义。
- “只选一个参会人”的白名单语义更接近说话人验证，不是分类；若候选集外存在更强注册人，必须回退为“未知/陌生人”，不能把所有片段都吸到唯一候选人上。
- [2026-08-14] 没有标准稿时把“血压幺幺八嗯二十六”标成疑似数字错误，实际标准内容就是 118、26 → 医疗录音精度评估必须先取得参考稿；没有真值时只能标为待复核，不能凭常识判定数值错误。
- [2026-08-14] 建议把 ASR 后端模型名直接暴露为接口参数，用户实际需要表达的是速度与精度的取舍 → 外部接口使用业务语义 `priority=speed|accuracy`，具体模型映射只保留在服务端内部。
- [2026-08-14] 把非流式接口的速度/精度模式直接等同于 Paraformer/Nano，遗漏了用户要比较的是同一 Nano 模型的切分策略 → 非流式 `priority=speed` 保持现有 Pyannote 分段 + Nano，`priority=accuracy` 使用整段 Nano；先固定模型再比较上下文完整性与耗时。
- [2026-08-17] 把 `20260814_154908.m4a` 的参考内容沿用到 `20260814_162334(1).m4a`，导致把不同录音的数字差异误判成模型错误 → 参考稿必须按文件名或文件哈希绑定；没有对应真值的录音只记录输出，不计算准确率。
- [2026-08-17] 看到 `accuracy` 超长自动降级后误以为可以直接取消 `priority`，忽略了短音频仍需显式选择速度或精度 → 保留 `priority`，默认 `speed`；只有显式请求 `accuracy` 且超过安全时长时才自动降级。
